# Soft / learned-token family: Gist Tokens, AutoCompressor, 500xCompressor

Ledger: `raw/ledger/soft_family.jsonl` (all paper quotes script-verified; 8 web-source lines are WebFetch renderings and are NOT script-verifiable, see end). Sources: Gist = arXiv:2304.08467v3 (NeurIPS 2023) [GT-060, GT-061, GT-067]; AutoCompressor = arXiv:2305.14788v2, "Adapting Language Models to Compress Contexts" (EMNLP 2023 per 500x reference list) [AC-080, AC-081, AC-087]; 500xCompressor = arXiv:2408.03094v1, 6 Aug 2024 (the supplied text is v1) [XC-070, XC-071].

REPO DEFECT (for the report): the repo's `papers/gist-tokens.pdf`, labelled "GIST: Generalizable In-Context Learning with Scalar Transformers, Zhang et al., arXiv:2401.09390", is an unrelated mathematics paper on the nonlinear q-Bernstein operator (math.FA) [ART-G06, ART-G07]. The real Gist Tokens paper is Mu, Li, Goodman, arXiv:2304.08467 [GT-060, GT-061]. The repo's AutoCompressor article says no paper could be located; the paper is arXiv:2305.14788 [ART-A01, AC-080, AC-081].

All three methods are model-internal: none can be applied to an API-only LLM. None of the three papers states this; it is inferred from the mechanism (flagged "inferred from mechanism" in each claim) [GT-008, AC-005, XC-004].

## Gist Tokens (method "GistTokens")

Profile
- Mechanism: soft/gist tokens. An LM is instruction-finetuned with a gist token inserted after the prompt and an attention mask that stops later tokens from seeing the prompt, so the prompt must be squeezed into the gist prefix [GT-001, GT-002, GT-003].
- What is trained: one new gist token (vocab + embedding row) and the LM itself via standard instruction finetuning; the paper does not say "full finetune" vs PEFT explicitly [GT-004]. Needs no extra training cost over instruction finetuning [GT-055]. Implementation is ~10 lines of mask code, no architecture change [GT-062].
- Output form: key/value activations on top of the gist tokens (a Transformer prefix) [GT-007]. The LM itself is the gist predictor, so the prefix is only meaningful to that same finetuned model (inferred from mechanism) [GT-005].
- Base models: LLaMA-7B (decoder-only, ~7B) and FLAN-T5-XXL (encoder-decoder, 11B) [GT-006].
- Closed/API models: not discussed; retrofitting a frozen LM with a smaller compressor is future work only [GT-008].
- Compression ratio: "up to 26x" with 1 gist token on the Human split; ratio = average prompt length of the split / number of gist tokens; compressed prompts are short instructions (~20 tokens train, ~26 Human split) [GT-009, GT-010, GT-011, GT-012]. k in {1,2,5,10} tried; insensitive to k; 10 gist tokens hurt LLaMA in some cases [GT-013, GT-014].
- Quality (metric ROUGE-L and ChatGPT win rate against the positive control; Alpaca+ Seen/Unseen/Human splits): LLaMA-7B Pos [GT-015], Gist [GT-016], Neg [GT-017], TF-IDF [GT-018]; FLAN-T5-XXL Pos [GT-019], Gist [GT-020], Neg [GT-021]. Seen: near-identical to Pos [GT-022]; OOD Human split: "slight drops" to 45.8% (LLaMA) and 42.5% (FLAN-T5) win rate [GT-023]. 50% win rate = parity with no compression [GT-024].
- The uncompressed baseline is the positive control (instruction-finetuned model without the gist mask), not the original LLaMA [GT-025].
- Human eval: 100 of 252 Human-split prompts, 3 annotators [GT-026]; LLaMA-7B gist 52.3% win over Pos (CI 46.1-58.4) [GT-027]; FLAN-T5-XXL gist 40.6% (CI 34.6-46.8, below parity) [GT-028].
- Exact strings: gist outputs are identical to the positive control's output ~50% (Seen), ~20-25% (Unseen), ~10% (Human); this is output identity vs the positive control, not a text-reconstruction test [GT-029]. Instruction details that must be copied verbatim are a named failure mode, with an example (FLAN-T5 answered "Culture" instead of "Arts & Culture") [GT-030, GT-031]. Runaway generations occur more than with Pos [GT-032].
- Limitations (authors): loses nuance of the instruction; evaluate before deployment [GT-033, GT-034]; FLAN-T5 generalises slightly worse OOD [GT-035]; very long / many-shot prompts not tested [GT-036]; max sequence length 512 (768 Human split) for LLaMA and 128 input for FLAN-T5 [GT-037, GT-038].
- Hardware / training cost: 4xA100-SXM4-80GB, 480GB RAM, 16 CPUs; ~7 h (LLaMA-7B), ~25 h (FLAN-T5-XXL); 3000 / 16000 steps; benchmarking on 1 A100 [GT-039, GT-040, GT-041, GT-042]. Data: Alpaca+, 130,321 examples [GT-056].
- Latency / FLOPs: measured as a single forward pass (one decode step, one input token) averaged over 252 Human instructions, PyTorch 2.0, 1 A100 [GT-043]. LLaMA-7B CUDA time per step [GT-044]; relative wall-time gain 6.8% vs no caching and 1.0% vs instruction KV caching [GT-045]; FLOPs gain 40% vs no caching and .11% vs instruction caching [GT-046]; FLAN-T5-XXL wall time 4.2% [GT-047], FLOPs 40% [GT-048]. Authors' summary 40% FLOPs / 4-7% wall time [GT-049]; vs instruction caching negligible [GT-050]; reason: memory time at small scale [GT-051]; a 2000-token KV cache only ~10% more expensive than none [GT-052].
- Storage: up to 26x more prompts cached than with full-instruction caching in the same storage; 1.05 MB per KV-cache token for LLaMA-7B [GT-053, GT-054].
- Reproducibility: code, data, checkpoints at github.com/jayelm/gisting [GT-057]; README: Apache 2.0 code licence, mixed data licence (Apache 2.0 + CC BY-NC 4.0), LLaMA checkpoints are weight diffs needing the base LLaMA-7B [GT-058, GT-059].
- Tasks: only Alpaca+ instruction following (Seen / Unseen / Human splits); NOT tested: coding, long-document QA/RAG, multi-turn chat, summarization benchmarks, structured data, math/reasoning, PII [GT-063, GT-064]. Coding questions may occur in the Human split but are not analysed [GT-065].
- Third-party cross-check: 500x authors describe Gist as needing LLM finetuning and handling prompts < ~30 tokens [GT-066].

## AutoCompressor (method "AutoCompressor")

Profile
- Mechanism: soft tokens. A pretrained LM is adapted to emit summary vectors (soft prompts from output states) for each segment of a document; vectors from all earlier segments are concatenated (summary accumulation) and prepended to later segments [AC-001, AC-003, AC-004].
- Training: unsupervised language-modelling objective, no labels [AC-002]. OPT-1.3B/2.7B fine-tuned on 2B Pile tokens [AC-006]; Llama-2-7B: base frozen, only summary-token embeddings + attention weights via LoRA (dim 16), 15B RedPajama tokens, 6,144-token sequences [AC-007, AC-008, AC-009].
- Output form: summary vectors (soft prompts), one or two orders of magnitude shorter than the text [AC-004]. Same-model use and no API support are inferred from mechanism [AC-005].
- Compression: OPT-2.7B 2,048 tokens -> 50 vectors = 40 tokens per vector [AC-017]; Llama-2 4,096 tokens -> 100 vectors [AC-018]; ICL 750 tokens of demonstrations -> 50 vectors per segment, 1-3 segments [AC-019, AC-020, AC-021]; retrieval passages of 512 or 50 tokens, 512 -> 50 vectors [AC-022, AC-086]; re-ranking passages are ~100 words so low compression [AC-023]. More vectors did not help; 50 best [AC-024, AC-025].
- Max length: 30,720 tokens is the training/eval SEQUENCE length for OPT-1.3B/2.7B (20 compression steps of shorter segments), not a segment length [AC-012, AC-013, AC-014]; Llama-2 AutoCompressor was trained on 6,144-token sequences and evaluated on 8,192-token documents; base window 4,096 [AC-008, AC-015, AC-016].
- Language modelling (perplexity): fine-tuned OPT no-context baseline 6.28 / 8.53 [AC-028]; AutoCompressor 6.14...5.93 in-domain, 8.39...8.10 OOD, i.e. gains of only 1.6%-5.6% vs the no-context baseline [AC-026]; Extended Full Attention reaches similar or slightly better with plain text [AC-027]. 30K models [AC-029, AC-030, AC-031, AC-032]. Llama-2: pre-trained [AC-033], Extended FA [AC-034], AutoCompressor [AC-035]; full-attention baselines beat the AutoCompressor with longer contexts [AC-036]; OOD gap larger [AC-037].
- ICL (accuracy, 11 datasets [AC-044], mean +/- std over 7 seeds [AC-045]): AutoCompressor zero-shot [AC-038]; 50 / 100 / 150 vectors [AC-039, AC-040, AC-041]; plain ICL 150 and 750 tokens through the same model [AC-042, AC-043]; pre-trained Llama-2 zero-shot / ICL150 / ICL750 [AC-046, AC-047, AC-048]. Summary vectors beat 150 plain tokens on 8/11 and 750 plain tokens on 8 tasks [AC-049, AC-050], but the Llama-2 AutoCompressor has substantially worse zero-shot and slightly worse ICL than its initialisation [AC-051, AC-052].
- Retrieval-augmented LM (OPT-2.7B, no extra finetuning [AC-053..AC-056]): Fused Summaries gains 1.04-3.74% perplexity vs REPLUG-512 up to 8.30% but 1.7x throughput over REPLUG top-2 [AC-055, AC-056, AC-057]; REPLUG top-10 beats it [AC-058].
- Re-ranking (NQ, BM25 candidates): only a Pareto plot; numbers not in text [AC-064, AC-078].
- Storage / compute: 5TB per 10B-token domain vs 51 TB (transformer outputs) and 3,276 TB (all attention states) [AC-060, AC-061]; 2.1TB / 5.4TB for the NQ passage corpus [AC-062]; throughput on 1 A100 without batching [AC-059]; loading latency assumed negligible [AC-063]. Training on one A100 80GB [AC-010, AC-011]; CUDA training memory 38/54/75 GB, RMT-2.7B OOM [AC-029, AC-030, AC-031, AC-032]. Authors: "simple and inexpensive" [AC-065].
- Limitations (authors): only OPT <= 2.7B and Llama 7B; summary vectors lose information vs full attention; more vectors do not always help; accumulation still quadratic [AC-066, AC-067, AC-068, AC-069].
- Exact strings: no reconstruction metric; vectors keep salient names/dates [AC-083].
- Reproducibility: code and models public [AC-070]; checkpoints on Hugging Face (Llama-2-7b-6k; OPT 2.7b/1.3b incl. 30k) [AC-072]; licence: GitHub page shows none (WebFetch, absence only, verify) [AC-071].
- Tasks tested: Pile/RedPajama language modelling (GitHub, FreeLaw etc. only as perplexity domains, no per-domain numbers), 11 ICL datasets, retrieval-augmented LM perplexity, NQ re-ranking [AC-073, AC-074, AC-075, AC-076, AC-077, AC-078, AC-082]. NOT tested: coding tasks, long-document QA answer accuracy, multi-turn chat, summarization, structured data, math/reasoning, PII [AC-079].
- Third-party cross-check: 500x authors call it limited to fine-tuned LLMs with complex training [AC-084]; AutoCompressor authors describe Gist as KV-prefix compression [AC-085].

## 500xCompressor (method "500xCompressor")

Profile
- Mechanism: soft / KV-value compression. Encoder = frozen LLM + trainable LoRA; decoder = the same original frozen LLM; ~0.25% extra parameters [XC-001, XC-002]. Only one base LLM is evaluated: LLaMa-3-8b-chat [XC-010, XC-011] (README says LLaMa-3-8b-Instruct adapters) [XC-068].
- Output form: per-layer KV values of 1, 4 or 16 compressed tokens (not embeddings, unlike ICAE) [XC-003, XC-007]. Usable by the original LLM without fine-tuning it [XC-006]; compressed KV is tied to that same LLM (inferred) and model internals are required, so no API-only use (inferred) [XC-004, XC-005]. The idea is "akin to Prefix Tuning" [XC-009].
- Compression ratio: 6x to 480x from compressing 96-480-token abstracts into 16, 4 or 1 tokens [XC-012, XC-013]; compressor input ~500 tokens, test texts 96-480 [XC-014, XC-015]; authors say prior work reported < 50x [XC-016]; tokens not equally used (16 -> 4 similar, 1 drops) [XC-017].
- Tasks: Arxiv-abstract regeneration plus extractive QA on ArxivQA, SQuAD, RE, HotpotQA, RACE [XC-072, XC-073]; ArxivQA and Arxiv test texts postdate Jan 2024 [XC-075]. NOT tested: coding, multi-turn chat, summarization, structured data, math reasoning, PII, long documents; RAG/ICL/reasoning only future work [XC-074, XC-063].
- Uncompressed baselines ("gold standards"): Instruct = full context + instruction [XC-018, XC-030]; Zero-shot = full context without instruction [XC-019, XC-031].
- Absolute QA (F1/EM): 16 tokens [XC-020] vs ICAE [XC-021, delta XC-022]; 4 tokens [XC-023] vs ICAE [XC-024, delta XC-025]; 1 token [XC-026] vs ICAE [XC-027, delta XC-028]. 500xCompressor loses to ICAE on SQuAD/HotpotQA at 16 tokens and on RE/HotpotQA at 4 tokens [XC-022, XC-025]; authors concede the advantage is not consistent outside information extraction [XC-044]; HotpotQA/RACE improve from 4 to 1 token [XC-045]. ArxivQA gains over ICAE 2.06-9.23 F1 / 0.56-7.20 EM and 18.62 F1 on RE at 1 token [XC-042, XC-043].
- "Percentage of capability retained": abstract says 62.26-72.89% [XC-032]; it is the Average-F1 column of Table 5, i.e. scores normalised so Instruct = 100 [XC-033, XC-034]: 16 tokens 72.89 [XC-036], 4 tokens 67.12 [XC-038], 1 token 62.26 [XC-040]; ICAE 71.16 / 66.01 / 40.90 [XC-037, XC-039, XC-041]; Zero-shot (no instruction) is 42.06 [XC-035]; average EM is 65.48-81.29 [XC-036, XC-040]. Agent arithmetic (not printed in the paper): the Average is the unweighted mean of the five per-benchmark normalised F1 values (e.g. XC-036 row: mean of 72.93, 70.79, 96.31, 60.09, 64.34 = 72.89); the ratio of the averages in Table 2 would give a different number. Base is LLaMa-3-8b-chat extractive QA only.
- Regeneration (reconstruction): scored by ROUGE-L-F and BLEU only (the brief's ROUGE-1 is not used); only differences vs ICAE appear in text, absolute scores are in Figure 3 [XC-046, XC-047, XC-048, XC-053]. No exact-match rate of regenerated text is reported [XC-053]. Table 1 example shows non-exact regeneration at 96 -> 4 tokens, e.g. "Kato modules" for "Kato complexes" [XC-049, XC-050, XC-051]. Authors claim names/numbers are accurately retained ("drill down analysis") but no such analysis appears in this text [XC-052].
- Baselines: only ICAE, no hard-prompt or Gist/AutoCompressor comparison [XC-054].
- Latency / compute: inference speed is explicitly NOT analysed [XC-055, XC-056]; only qualitative claims [XC-057, XC-008]. Hardware not reported [XC-060]. Training: steps/lr/batch 4 [XC-058]; 2,353,924 Arxiv abstracts, 250,000 ArxivQA training pairs [XC-059].
- Limitations: small corpora [XC-061]; no limitations section [XC-062]; tokens unevenly used [XC-064].
- Reproducibility: paper says code/data/models/demo open [XC-065]; README (WebFetch): CC BY 4.0, HF datasets/models "not open to the public", LoRA adapters on LLaMa-3-8b-Instruct, "ACL 2025 Main" [XC-066, XC-067, XC-068, XC-069]. The supplied paper text states no venue [XC-071].
