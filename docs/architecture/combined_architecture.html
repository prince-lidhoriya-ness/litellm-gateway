Combined LLM gateway: context engineering + prompt compression + cache-aware execution

One LiteLLM proxy. Callbacks run in the fixed order of litellm_config.yaml: auth and limits, then context engineering (new, context_engineering/), then prompt compression (prompt_compression/), then model routing. Smart routing is the proposed stage from smart-router; it is not part of this repository yet.

context engineering (new) prompt compression (existing) smart-router (proposed) LiteLLM / infrastructure state
  • Defaults: budget, duplicate folding, masking and cache-aware construction on; JIT retrieval and compaction off (opt-in flags).
  • JIT retrieval is skipped on providers that cache prompts unless explicitly allowed: query-dependent selection would change the cached prefix.
  • Measured results: reports/context-engineering/REPORT.md. Design: docs/context-engineering-blueprint.md, context_engineering/README.md.
